两行命令，不需要重装任何东西：

下面是我怎么找到这一行的。只想要结果的话，到这里就够了。

症状

在 Ubuntu 24.04 上 apt install retroarch retroarch-assets，把界面语言改成简体中文，得到的是这个：

位置和数量都对得上。上面的第一行本来是 1火焰纹章_封印之剑，现在是 1????_????；第七行本来是 侵略者[TGB](简)(JP)(64.04Mb)，现在是 ????[TGB](?)(JP)(64.04Mb)。

菜单也一样，主菜单 变成 ????，设置 变成 ??。

但英文界面完全正常。 这是整件事最坑的地方 —— 你不去改语言，永远看不到这个 bug；而一旦看到，它长得像另一个完全不同的问题。

为什么这个 bug 特别难查

两个原因叠在一起：

  • 英文完全正常。 界面看起来是健康的，所有图标、布局、交互都对，只是换个语言才炸。
  • 症状看起来就是「字体缺字」。 任何人看到满屏 ? 的第一反应都是「这个字体没有中文字形，去换个字体」—— 而换字体永远不会有用。我在这条路上花掉的时间最多。

下面按顺序记录我排除掉的三个假设，和最后找到的东西。

排除 ①不是字体缺字

第一反应：界面用的字体里没有汉字。Debian 的 assets 包把主界面字体指向 Roboto，那确实是个纯拉丁字体。

于是我把它换成了 Noto Sans CJK SC —— 从系统里的字体集合里单独提取出来的，44,810 个字形，简体繁体全覆盖。换之前验证过 设置、载入核心、我的最爱 这些字都在里面，一个不缺。

结果是：

不是缺字。字体有这个字，但界面没用它来画这个字。

排除 ②不是字体格式

接下来想到的是轮廓格式。Noto Sans CJK 是 CFF（PostScript 轮廓），文泉驿微米黑是 TrueType（glyf 轮廓）。有些老的字体渲染器只吃 TrueType，不认 CFF —— 如果 RetroArch 用的是那种，就能解释为什么换了字体也没用。

两种都试了，结果一模一样。不是这个。

排除 ③不是字体没加载

到了这里其实已经走进死胡同了。真正让我转向的是另一个测试 ——

把语言切回英文，但字体保持同一套。 然后打开游戏列表：

这一张图把范围锁死了。它同时证明了四件事：

  • 字体是好的 —— 它能渲染中文；
  • 渲染链路是好的 —— 就在同一个菜单、同一屏像素里；
  • 文件路径是对的 —— RetroArch 确实读到了这个字体；
  • 唯一剩下的变量是语言设置本身。

也就是说：当语言不是英文时，RetroArch 去加载了另一个字体文件，而那个文件不存在。

找到根因一个文件名对不上

源码在 GitHub 上，当时网络不通。但二进制就在本地，直接问它：

korean-fallback-font.ttf

再看 Ubuntu 的包实际装了什么：

dpkg -c retroarch-assets_1.7.6+git20230911+dfsg-1_all.deb | grep -i '\.ttf'
.../assets/pkg/chinese-font.ttf          -> DroidSansFallbackFull.ttf   ← 旧名字
.../assets/pkg/fallback-font.ttf         -> DejaVuSans.ttf
.../assets/pkg/korean-fallback-font.ttf  -> NotoSans-Black.ttf
.../assets/pkg/osd-font.ttf              -> DejaVuSansMono.ttf

chinese-font.ttf  ≠  chinese-fallback-font.ttf

差一个 -fallback。

这个包是 2023 年 9 月的快照（版本号里的 git20230911），而 retroarch 本体已经是 2024 年 4 月的 1.18.0。中间上游把文件改了名，Debian 这边的 assets 包没跟上。

顺带看了下上游官方发的资源包，里面的名字是对的：

# https://buildbot.libretro.com/assets/frontend/assets.zip
pkg/chinese-fallback-font.ttf        ← 官方有
pkg/thai-fallback-font.ttf           ← Debian 包没有
pkg/ethiopic-fallback-font.ttf       ← Debian 包也没有
pkg/fallback-font.ttf
pkg/korean-fallback-font.ttf
pkg/osd-font.ttf

所以受影响的不只是中文。泰文和埃塞俄比亚文（阿姆哈拉语等）的兜底字体 Debian 包压根没有，症状会完全一样。另外「韩文兜底」被指向了 NotoSans-Black.ttf，那是个不含韩文字形的拉丁字体，看起来也是错的。

那四个位置

RetroArch 的界面字体是分层的：一个主字体负责拉丁字母，缺的字再去兜底字体里找。中文界面会去这四处找：

  • assets/ozone/regular.ttf界面主字体
  • assets/ozone/bold.ttf界面粗体
  • assets/pkg/chinese-fallback-font.ttf中文兜底 · 缺它就全变 ?
  • assets/pkg/fallback-font.ttf通用兜底

Debian 的包里这四个全是指向系统字体的符号链接。单独把 deb 解包出来用（不装到系统里）会得到一堆断链，那个 chinese-fallback-font.ttf 更是连名字都不存在。

为什么会变成「?」而不是别的

主字体（Roboto）只有拉丁字形。FreeType 去查一个汉字，查不到，于是按缺字处理画一个 ?。正常流程是：主字体查不到 → 去兜底字体查 → 找到就画汉字。兜底字体没加载，第二步就断了，于是每一个汉字都落到 ?。拉丁字母在主字体里查得到，所以完全正常 —— 这就是为什么故障长得这么有欺骗性。

修好之后

不该忘掉的那件事

折腾这一通的起因其实很简单 —— 想玩个游戏。顺便验证一下存档还在不在：

这不是你配错了

如果你也撞上这个，值得顺手报上去。这不是你本地配置的问题，是发行版打包的问题，而且是能修的那种：

  • 报给谁 —— Debian BTS 或 Ubuntu Launchpad，包选 retroarch-assets。
  • 修什么 —— 把 pkg/chinese-font.ttf 改名成 pkg/chinese-fallback-font.ttf，补上缺失的 thai-fallback-font.ttf 和 ethiopic-fallback-font.ttf，再把 korean-fallback-font.ttf 指到真正含韩文字形的字体。
  • 更根本的修法 —— 别手工维护这些符号链接了，直接发上游 assets.zip 的内容，文件名的漂移就不会再发生。
附录：完整的排查命令（可直接复现） 
# 1. 确认症状：切成简体中文（11 = 繁体，12 = 简体）
sed -i 's/^user_language = .*/user_language = "12"/' ~/.config/retroarch/retroarch.cfg
#    ⚠ 改配置前先把 retroarch 退出。它在退出时会把内存里的配置
#      写回文件，顺序反了你的修改会被它盖掉。

# 2. 二进制到底在找哪些字体文件
strings -a /usr/bin/retroarch | grep -E '\.ttf'

# 3. 包里到底装了什么
dpkg -c /var/cache/apt/archives/retroarch-assets_*.deb | grep -i '\.ttf'
#    或者已装好的机器上：
ls -l /usr/share/libretro/assets/pkg/

# 4. 对不上的那个名字，补上
sudo apt install fonts-droid-fallback
sudo ln -sf ../../../fonts/truetype/droid/DroidSansFallbackFull.ttf \
    /usr/share/libretro/assets/pkg/chinese-fallback-font.ttf

# 5. 验证字体里确实有汉字（可选）
python3 -c "
from fontTools.ttLib import TTFont
cm = TTFont('/usr/share/fonts/truetype/droid/DroidSansFallbackFull.ttf').getBestCmap()
print([c for c in '主菜单设置' if ord(c) not in cm] or '汉字齐全')
"
